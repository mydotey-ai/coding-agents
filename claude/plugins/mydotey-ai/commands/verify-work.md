# verify-work

检查当前会话中所有需求、计划、任务的完成情况。扫描整个对话上下文，提取所有需求、计划任务、Task List 任务，核对是否全部完成，有没有遗漏、敷衍或偷工减料。

## 需要检查的三类工作

1. **需求** — 对话上下文中用户提出的所有需求（每一轮）
2. **计划** — plan 模式遗留的计划文件中的任务
3. **任务** — Task List 中的所有任务

## 执行步骤

### 1. 提取并整理所有待办工作

#### 1.1 提取需求（来自对话上下文）

扫描整个对话历史，提取**每一轮**用户消息中的需求：

```
**第1轮（原始需求）**：
- 需求1.1：[原话摘要]
- 需求1.2：[原话摘要]

**第2轮**：
- 需求2.1：[原话摘要]
...

每一轮都要记录，来源是用户的哪条消息。
```

#### 1.2 提取计划任务（来自计划文件）

检查是否存在计划文件：
- 常见路径：`.claude/plans/`、`CLAUDE.md` 中提到的计划
- 读取并列出计划中的每一步任务
- 标记计划来源文件

#### 1.3 提取任务（来自 Task List）

使用 TaskList 工具列出所有任务：
- 记录每个任务的 subject、status、blockedBy
- 分类：pending / in_progress / completed / blocked

### 2. 合并去重并分类

将三类工作合并，去重后分类：

| 来源 | 任务项 | 状态 | 证据 |
|------|--------|------|------|
| 需求-第1轮 | xxx | ✅/❌/⚠️ | 产出物 |
| 计划-file.md | xxx | ✅/❌/⚠️ | 产出物 |
| Task List | xxx | ✅/❌/⚠️ | 任务状态 |

### 3. 逐条核对完成情况

对于**每一条**工作项，检查：
- ✅ **是否已明确完成** — 有实际产出物作为证据
- ❌ **是否遗漏** — 要求了但没做
- ⚠️ **是否敷衍** — 做了但没做到位

**常见偷工减料行为（必须识别）：**

| 类型 | 特征 | 举例 |
|------|------|------|
| 跳过步骤 | 说"简单"就跳过 | "这个配置很简单，不需要验证" |
| 功能缺失 | 用户要 A，只做 B | 用户要"完整功能"，只做了"基础功能" |
| 临时方案 | 说"先用这个"就当成完成 | 用 hardcode 数据代替真实逻辑 |
| 文档缺失 | 说"后面再补" | 测试代码、注释、文档都没写 |
| 遇阻退缩 | 说"做不了"就放弃 | 遇到问题不解决，直接跳过 |
| 表面功夫 | 形式上有，但内部是空的 | 有函数签名但实现是 pass/throw |
| 需求遗漏 | 只做部分就停止 | 用户要 3 个功能，只做了 1 个 |
| 推卸甩锅 | 说"用户没说清楚" | 不主动确认就跳过 |
| 计划跳步 | 计划中有 5 步，只做了 3 步 | 说"后面几步不需要" |

### 4. 验证实际产出物

对已完成的工作，验证产出质量：
- 修改的文件是否存在预期改动
- 创建的文件是否内容完整
- 命令执行是否有预期输出
- 是否有 TODO/FIXME/XXX 等未完成的标记
- 是否有被注释掉的代码但没说明原因

### 5. 输出检查报告

```
## 工作完成度检查报告

### 汇总
- 需求总数: N 个（来自对话上下文）
- 计划任务数: N 个（来自计划文件）
- 任务数: N 个（来自 Task List）
- 已完成: N 个
- 待完成: N 个
- 被阻塞: N 个

### 详细检查结果

#### 需求（对话上下文）
| 轮次 | 需求内容 | 状态 | 证据 |
|------|----------|------|------|
| 第1轮 | xxx | ✅/❌/⚠️ | 产出物 |
| 第2轮 | xxx | ✅/❌/⚠️ | 产出物 |

#### 计划任务（计划文件）
| 来源文件 | 任务 | 状态 | 证据 |
|----------|------|------|------|
| plans/xxx.md | 步骤1 | ✅/❌/⚠️ | 产出物 |
| plans/xxx.md | 步骤2 | ✅/❌/⚠️ | 产出物 |

#### Task List 任务
| 任务 | 状态 | blockedBy |
|------|------|-----------|
| xxx | ✅/⏳/🚫 | - |

### 偷工减料检查结果
[列出发现的任何问题]

### 结论
✅ 全部完成 / ⚠️ 存在 N 个问题需要修复
```

## 注意事项

- **必须检查所有三类工作**：需求、计划、任务
- **扫描整个会话上下文**，不要遗漏任何一轮
- **每条工作项都必须有明确结论**
- **严格要求**：即使任务看起来简单，也要验证完成质量
- **证据说话**：必须有实际产出作为完成依据
